## Android build tools (used only to produce the APK, never installed with the app)

These are fetched into a local cache by `npm run android:apk` when the machine has no Android
SDK, and they are used only while building. None of them is bundled into the installed app, and
none of them is a dependency of the project or of the shipped JavaScript.

| Tool | Version | License | Used for |
| --- | --- | --- | --- |
| aapt2 (Android Asset Packaging Tool 2) | 2.20 | Apache-2.0 | Compiles the resources and links AndroidManifest.xml |
| d8 (R8/D8, from the Android build tools) | 8.2.2 | Apache-2.0 | Converts the compiled Java classes into classes.dex |
| apksigner (and its libraries) | from build-tools | Apache-2.0 | Signs and verifies the APK |
| Eclipse Compiler for Java (ECJ) | 3.45.0 | EPL-2.0 | Compiles the shell's Java sources without a JDK compiler |
| Temurin OpenJDK (via the jdk4py PyPI package) | 25.0.2 | GPL-2.0 with the Classpath Exception | Runs aapt2, d8 and apksigner |
| npm mirrors: `aaptjs3`, `@drxiaozhi/minapk` | latest | MIT (packaging only) | Serve the tools above without an Android SDK install |

The debug signing key used by `npm run android:apk` is the standard Android debug keystore
(`CN=Android Debug`). It is not a secret and not a release key: see `android/README.md` for how
to sign with your own key.

## Full license texts

Every package above is distributed under its own license text inside `node_modules/<package>/`
(LICENSE, LICENSE.md, COPYING or an equivalent file, plus the `license` field in its
`package.json`). Because these packages are consumed unmodified as dependencies, their license
texts are preserved by npm at install time. When `npm ci --omit=dev` is used to install only the
runtime dependencies, the two runtime packages listed above are MIT licensed and their license
texts are included in their published tarballs.
